### zerro-4u9 — Invalid Date в FilterDrawer · СДЕЛАНА

Коммиты `86aac583` и `16acab2c`, файл
`src/3-widgets/transaction/TransactionList/TopBar/FilterDrawer.tsx`.

Первый коммит — минимальный фикс из постановки: обе границы проходят через
`isValidDate`, `NaN-NaN-NaN` в условие больше не уезжает.

Второй — по находке ревью Codex, дефект в моей же правке: отдавать
`undefined` на каждый промежуточный `Invalid Date` мало. `value` у
`DatePicker` — controlled, он схлопывался в `null`, и MUI стирал
незавершённый ввод прямо во время правки уже заданной даты (удалил одну
цифру — поле очистилось). Обе границы вынесены в компонент
`FilterDatePicker` со своим черновиком: промежуточное значение живёт
локально, наружу уезжает только валидная дата либо явная очистка. Внешняя
смена условия («Очистить всё», выбор в календаре) доезжает в поле через
`useEffect`.

Чем проверено: `npx tsc --noEmit` → exit 0 (дважды, после каждой правки).
`npx vitest run` не гоняет FilterDrawer вовсе — компонентных тестов на него
в репо нет, а сам прогон красный по чужой причине (см. zerro-1qk ниже).
Поведение в браузере **не проверялось**: дев-сервер ночью не поднимался.

Ревью Codex: отработало, одна находка P2 по собственной правке, починена
отдельным коммитом. Замечаний про чужой код вокруг не было.
